# example.game3 context

Started from the owner's gams3/plugins/game C/Sokol triangle, adapted into an
independent experiment with native macOS/Metal and browser WASM/WebGL2 targets.
Current milestone: a first survivor combat loop in a fixed tilemap arena, using
shared tilemap/sprite pipelines and procedural textures. Movement, tile collision,
four ordinary enemy archetypes, automatic aimed shots, contact damage, XP gems,
health/kills/level/XP/timer HUD, paused level-up choices, a three-wave 90-second
countdown, a two-phase final boss, optional orbiting blades, win/loss and R
restart are implemented. Authored scenarios and further weapons are not.
gams.json now adds Content Files, BulletML preview and a Nodegraph packaging
pipeline. The original minimal config was owner-verified; expanded authoring
has CLI/engine checks, with native GUI checks pending. The game renderer is not
embedded in a Host View.

Planned game direction: survivor-style free movement, automatic attacks and XP
upgrades, authored encounters and a final boss, with title/game/result/credits.
BulletML authoring and pack generation use GAMS; both game targets now embed the
same RSPK bytes and decode them once into owned immutable C IR. The independent
VM is unchanged. Balance/wave data and director integration remain separate slices. Do not port old generated Odin
decoders or the director as part of authoring setup.

Ownership:
- gams.json: explicitly pinned published Unit sources. Existing FS/Layout and
  six shell UI Services/theme are retained; add Lua/respack 0.2.0, BulletML View
  0.2.0 and Nodegraph/internal-node editor 0.1.0. No unpublished sibling Unit
  source is substituted. Exact known filenames route to BulletML/Nodegraph;
  current Files matches basename/final extension, not compound-extension globs.
- content/: canonical authored pattern JSON plus content/gams graph, Lua nodes,
  schema, compiler and optional CLI launcher. Root ng/compile-graph.lua is the
  compatibility entry hard-coded by the released View, forwarding to the single
  content-owned compiler. See content/README.md and PROVENANCE.md.
  make content runs the same graph/compiler through the installed GAMS CLI and
  cached configured FS/Lua/respack Units, then embeds its output. The one-slot RSPK
  and generated byte-array header live under build.nosync/content, never tracked
  or written into game source. Ordinary builds/Pages use content/gams/pack.mjs:
  Node-only encoder of the registered five-node packaging contract and schema,
  not a Lua interpreter. It rejects unsupported topology/custom node script bytes,
  preserves a newer GAMS pack, and requires ranger exactly once at vector index 0.
  Node script hashes guard this local adapter's semantic compatibility only, not
  dependency integrity/updates. Changed script semantics require adapter review.
  Make validates required inputs even on no-op builds, so deleted source files
  cannot disappear from wildcard prerequisites and silently reuse stale output. GAMS
  install/cache remains Host-owned. Future cache additions are ignored; older
  already-tracked cache files are unchanged, not canonical editable sources.
  Native 2.0.6 CLI produced two patterns/344 bytes with published components;
  preview engine checks passed. Real GAMS baseline and modified spread/delay/speed
  packs matched portable bytes and reached actual native/WASM simulation with
  no C edits (GAMS_INTEGRATION=1 test/packed-game.test.mjs). Three-pane
  GUI/edit-save/Run still need owner smoke; CLI evidence is not GUI evidence.
- game/main.c: procedural textures, shared keyboard state and simulation/render
  integration; rendered tiles come from the collision map source. Reward UI uses
  four 2x2 cards before blade unlock, then six 3x2 cards. Bordered cards share
  layout/hitboxes, assert label widths and fit the minimum 320x240 viewport.
  app_choose_reward accepts normalized canvas/window coordinates, converts via
  the same viewport zoom as rendering, and shares selection guards with keys.
  Native mouse positions normalize against logical window size (not framebuffer
  size); browser pointer input normalizes CSS canvas bounds, independent of DPR.
- game/bulletml/: allocation-free independent C11 port of the demo event VM;
  immutable borrowed IR, bounded stack/params, synchronous event callback,
  expressions/references/waits/repeats and motion targets. No generated decoder,
  GAMS, ECS or renderer dependency. See its README and provenance for exact
  semantics/limits; this is demo-compatible, not a full XML/spec implementation.
- game/bulletml/pack.{h,c}: newly authored strict RSPK v1/schema-specific decoder,
  separate from the VM. Owns all decoded arrays/strings in caller-provided bounded
  stationary storage; no allocator, filesystem or platform API. Wire values map
  explicitly to VM enums, not C layout casts. Guards structural/reference/capacity
  errors at decode; expression execution/grammar still uses VM assertions.
- game/patterns.{h,c}: embedded-pack startup/binding adapter and 60 Hz convention.
  sim_init calls sim_patterns_init once per instance. sim_ranger_pattern() returns
  const borrowed IR from stationary static storage. Startup rejects unsupported
  child actions/world commands for the selected ranger, even before wave two.
  Retry resets actors, never decodes over live borrowed content. Pack changes
  require rebuilding/restarting native or Reload in the browser, not hot-loading.
  Ranger's canonical JSON exercises repeat/wait/fire refs and a $1 offset;
  speed remains pixels per VM frame converted to pixels/second by the host.
- game/sim.{h,c}: platform-independent 120 Hz movement and swept tile collision;
  normalized diagonal movement, 64 pixels/second, 0.25-second frame-time cap.
  Also owns bounded enemy/projectile pools, deterministic perimeter spawns,
  BFS chase routing, nearest-visible auto-fire, swept projectile hits, damage
  cooldowns, kills, XP drops/collection, level-up freeze and frozen death state.
  The 64-slot gem pool merges overflow value into an existing gem. Initial XP
  threshold is 3, rising by 2 per level; surplus XP queues distinct choices.
  sim_choose_upgrade accepts shot damage/rate, movement speed, blade unlock,
  blade damage/count/spin choices;
  capped attack rate consumes nothing. sim_init fully resets the run and stats.
  Enemy kinds are chaser, runner, brute, boss and ranger. Authored, non-linear XP
  rewards are 1 for chasers, 2 for fast runners, 3 for rangers and 5 for brutes (3x chaser HP,
  5x XP),
  independent of remaining HP/overkill. Boss death ends the run without XP.
  Gem tint reflects stored value: purple 1, blue 2–4, gold 5+, including merges. Waves change every 30 active
  seconds; at 90 seconds the arena clears for a guaranteed boss, with no regular
  spawns afterward. Boss HP is 120 and its hard-coded eight-shot ring speeds up
  at half health. A separate 32-shot hostile pool prevents weapon starvation.
  Boss death sets won, clears threats and freezes the world before hostile hits;
  both won and dead require a full restart. The run clock pauses for choices.
  Blades unlock with count 2, damage 1, radius 22 and phase step 4/960 per tick
  (2-second revolution). Count caps at 4; spin adds 2 up to 12 (2/3-second orbit).
  Blade damage is independent from shot damage. sim_blade_position shares the
  wall-clipped, interpolated circle with rendering; no platform trig library.
  Sweeps cleave; a per-enemy 30-tick blade cooldown prevents per-frame stacking,
  and fresh spawns reset it. Both weapons use shared hit_enemy kill/XP/victory
  handling; blade slots are independent from projectiles and do not block enemy
  shots. Upgrade/result freezes include the orbit; sim_init resets the weapon.
  Rangers enter waves 2/3, with 4 HP/22 px/s, approach/hold/retreat distance AI,
  LOS-gated VM ticks every two simulation steps, short-wait warning and aimed
  three-shot fans. Reacquisition restarts a full wind-up. Hostile saturation
  drops events without replaying them. First host adapter accepts linear child
  bullets only; unsupported child actions/motion events assert. VM commands
  support them independently, but world interpolation is deferred. Existing
  boss rings are not migrated. Enemy death stops its VM; reset clears all state.
- game/font.h: small authored 5x7 uppercase/digit HUD glyphs, rasterized into
  the procedural atlas; no downloaded font or new rendering dependency.
- game/app.h: shared app callbacks and eight-binding scalar browser key ABI.
  App frame accepts elapsed seconds. Native uses Sokol duration; browser uses
  requestAnimationFrame timestamps, resetting its clock/input on focus loss,
  visibility changes and pause. WASD/arrows remain separate held bindings.
  Browser retry() translates to the same R key event as native; retry applies
  only to won/dead runs and clears held movement and facing. choose_upgrade(0..5)
  maps UI slots to the same top-row 1–6 events as native (not raw simulation
  upgrade enum values). Existing 0–2 semantics are unchanged. Key 4 unlocks blades,
  then upgrades blade damage; 5/6 upgrade count/spin only after unlocking; accepted choices clear
  held movement and paused frame-time debt. Key repeats cannot consume choices.
  choose_reward(x,y) is the browser's normalized pointer ABI; only primary,
  unmodified canvas clicks while active are forwarded. MAX/gap/outside-card
  clicks consume nothing. Card selection still uses the same simulation enum.
- game/render/: C renderer API, instanced tilemap/sprite pipelines and adapted
  shaders; README.md documents the contract, PROVENANCE.md records original
  inputs. No external artwork or packed resources.
- game/triangle-sapp.glsl: retained shader-generation fixture, no longer drawn.
- gams_modules/: installed Unit cache; do not edit as canonical source.
- game/osx/: Sokol native application entry point and Metal implementation.
- game/web/: freestanding WASM entry point, libc/GL shims, tracked JS bridge,
  and standalone runner. Movement input crosses the scalar key/release ABI;
  frame time is supplied in seconds. Legacy pointer/layout exports are retained
  but unused by player movement.
- game/vendor/: version-control-ready Sokol header snapshots, including official
  sokol_glue.h; embedded licenses preserved. Existing files are never downloaded
  again by ordinary builds.
- .github/workflows/pages.yml: Ubuntu 24.04 + Zig 0.17.0 + Node 22 web build/test
  on release pushes and PRs targeting release. Only release pushes/manual runs
  on release may deploy build.nosync/web/ through github-pages, with Pages/OIDC
  permissions isolated to deployment. One-time Pages source setting must be
  GitHub Actions; existing environment approval/branch rules still apply. No
  native build, automatic remote setting changes or secret/PAT requirement.
  Only four production files are uploaded; Pages tests check the file set and
  repository-subpath links. Actual hosted execution/publication awaits a push.
- Makefile and test/: independent build and WASM/JS ABI verification, including
  timed-run and orbiting-blade regression tests. test/scene.c includes the real app in a separate
  test-only WASM for staged wave/boss/victory render checks; the production
  binary has no test-stage exports. Generated fixtures stay in build.nosync/.
- SOURCE.json: original source locations/revision and pre-adaptation hashes.
- game/**/*.glsl.h: generated C shader bindings intentionally kept with source
  for version control. No manual edits; generated with -f sokol for WebGL2/Metal.
- tools/: ignored downloaded compiler and optional GAMS Host at gams.app;

- build.nosync/: generated binaries, embedded content pack/header under content/,

Renderer scope excludes asset loading, decoder/director generation, copied
game1/game2 code or content, GAMS Unit release machinery, and new rendering libraries.
Standalone Pages automation belongs to repository build/deployment tooling, not
renderer or Host integration. The original
absolute /game/clear-color.rgb dependency is removed for this triangle milestone.
The JS bridge is taken from gams3's tracked examples/demo/game/web source;
the original plugins/game Makefile's cmd/browser/util bridge path is absent.

The legacy web shims/bridge are prototype infrastructure, not a general-purpose
runtime: bump allocation has no reclamation (reload uses fresh WASM memory),
and several GL operations are incomplete. Validate/implement each new graphics
capability before gameplay uses it. WASM assertions now trap instead of disappearing.
Native launch verification: Zig 0.16.0 with Xcode macOS 27.0 SDK builds and
passes make smoke-native (three real Metal frames followed by normal shutdown).
The native SDK uses the Zig driver --sysroot option. Callback definitions must
have explicit prototypes: init_with_gl(void) matches Sokol's void (*)(void);
the old unspecified-argument definition trapped in ReleaseSafe's function-type
check. Native compilation enforces -Werror=strict-prototypes. A recipe regression
runs in make test; the GPU smoke test is separate because it needs a macOS GUI.

Current renderer validation with Zig 0.17.0: make native, make smoke-native,
web build and make test pass; Chrome/WebGL2 fixture verified visually.
The native recipe uses -F/System/Library/Frameworks alongside --sysroot:
Zig prefixes framework search paths with the SDK itself. The earlier absolute
SDK-prefixed -F path was prefixed twice under Zig 0.17 and failed framework
lookup; a recipe regression now guards against that duplication. The native
smoke test draws three Metal frames and shuts down successfully.

Dependency policy: the files themselves are the snapshot. Each Sokol header
and the host's shader compiler is an ordinary Make target with no prerequisites.
Only missing files download, by default from upstream master. Existing bytes,
including local changes, are untouched; no lock, checksum verification, downloader
script or update targets exist. SOKOL_URL/SHDC_URL may override download sources,
but changing a URL does not refresh existing files. Remove desired files to fetch
again, then review and test the new snapshot; fetching one header may mix upstream
versions. Downloads use temporary files so failed requests leave no partial target.
Generated headers are adjacent to shader sources; normal builds handle regeneration
and include dependencies. make clean removes build metadata as well as binaries,
preserving tools and headers; the next build restores missing shader depfiles.

Optional Host download: make tools/gams.app queries the latest published release
of kkgams/gams, selects its macOS Apple Silicon ZIP and installs GAMS.app as
tools/gams.app. This ordinary directory target has no prerequisites: an existing
app stays untouched. Download/extraction staging lives under build.nosync/ and is
removed on success or failure. The target rejects unsupported hosts and malformed
releases/archives. It does not launch the app or integrate this experiment with
the Host, and is not required by all/deps or standalone builds. make clean retains
it; remove the app explicitly to fetch the latest release again.
